## iOS — RTSPCameraServer

### 本分支(`claude/dazzling-varahamihira-07671b`):Phase 3 — Local MP4 Recording 除錯與驗收

延續 [2026-09-04](2026-09-04.md) 的決定:先不合併 `/Volumes/Crucial` 那份平行 iOS 實作(GPS/Overlay/SRT),專心把本分支的 Phase 3 debug 完。今天在使用者實機(Sian-Ci's iPhone,iPhone 15 Pro)上反覆測試、抓出並修掉了好幾個真實 bug。

#### 建置環境
- `xcode-select` 原本指向 Command Line Tools 而非 Xcode.app,導致 `xcodebuild` 失敗,切換後(`sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`)+ Xcode GUI 手動觸發一次簽章,才解除「No Account for Team」的問題(與 09-04 日誌記錄的現象一致)。

#### 找到並修正的 bug
1. **`Info.plist` 缺少 `UIFileSharingEnabled`**:錄好的 mp4 完全無法從「檔案」App 取出,容易讓人誤以為沒存到。已加上 `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`。
2. **`AVAssetWriter` 沒有設定 `movieFragmentInterval`**:一旦錄影中途被中止(App 被砍、camera session 中斷等),`moov` box 只有在 `finishWriting()` 完成時才會寫入,中途中止會留下完全無法播放的檔案(`ftyp`+`mdat` 但沒有 `moov`)。已加上每 2 秒一次的 movie fragment,讓中途中止也保留可播放內容;`stop()` 走到 `cancelWriting()` 的分支也補上錯誤回報。
3. **`RTSPServer` 的 `NWListener` 沒有 `allowLocalEndpointReuse`**:快速 Stop/Start 時撞到 `Address already in use`。已加上這個參數。
4. **`LocalRecorder.maybeStartSession()` 只用「第一個影像 frame」的時間戳當作 session 起始時間**:麥克風跟相機的擷取延遲不完全同步,第一筆音訊樣本的時間戳偶爾會早於這個起始時間,導致該筆音訊被 `AVAssetWriter` 拒絕。已改成取影像/音訊兩者最早的時間戳。
5. **(本次最主要的根因)`AACEncoder` 建構的 `CMFormatDescription` 沒有帶 AAC 的 magic cookie(AudioSpecificConfig)**:`AVAudioFormat(settings:)` 產生的 format description 不含 magic cookie,導致 `AVAssetWriterInput.append()` 對音訊樣本幾乎必然失敗(`AVFoundationErrorDomain code=-11800` / `NSOSStatusErrorDomain code=-12633`),只有影像軌正常、音軌全滅。已改成用 `CMAudioFormatDescriptionCreate` 手動帶入 magic cookie 建立 format description,修好後音訊 append 完全正常。
6. **`RTSPServer.stop()` / `CameraCaptureManager.stop()` / `AudioCaptureManager.stop()` 都是非同步(`queue.async`)**:呼叫後立刻返回,但底層 socket / 相機硬體其實還沒真正釋放。連續 Start → Stop → Start(不關 App)時會撞上「舊資源還沒放、新的就要搶」的競爭狀態,重現為 RTSP `Address already in use` 或相機 `FigCaptureSourceRemote` 忙碌錯誤。已全部改為同步等待(`queue.sync` / semaphore),確保 `stop()` 返回時資源保證已釋放。

#### 新增功能
- **錄影完成後自動存進「照片」App**(`PHPhotoLibrary`),取代原本只能透過「檔案」App 挖 Documents 的方式;需要 `NSPhotoLibraryAddUsageDescription` 權限,存檔失敗時保留在 Documents 當備援,不會遺失錄影。
- 存檔狀態文字加上版本標記(`latestPhotoSaveToken`):避免快速連續錄影時,前一次錄影的非同步存檔回呼在畫面切到下一次錄影後才觸發,把當前狀態文字覆蓋成舊的結果。

- 實機測試已確認:1080p、Audio+Video、單次 Start→Stop 錄影乾淨(無 append 錯誤)、可正常存入「照片」App。
