# 開發日誌 2026-09-04

## Android — Camera2/MediaCodec RTSP server 重寫

延續先前 Phase 1-3（單一 H.264 RTSP 串流 → AAC 音訊 → 本地 MP4 錄影，皆已驗收 PASS），今天完成：

### Phase 4 — Secondary Stream：PASS / Closed
- 新增副流 H.264 encoder（320×240），透過 Camera2 多 Surface capture session 與主流同時輸出，RTSP 新增第 3 條 video track（channel 4/5，payload 98）。
- 實機驗證：3-surface capture session 成功、SDP 正確廣播 3 軌、主副流同時串流、10 分鐘 soak（18004 封包/軌、DTS 0 次非單調）、RTSP reconnect、Start/Stop/Start，皆通過。
- **已知限制（記錄追蹤，非阻塞）**：副流設定 5fps，但實際仍以 ~30fps 運行（僅解析度縮小）。原因是 Camera2 單一 CaptureRequest 以統一速率驅動所有掛載的 Surface，`MediaCodec.KEY_FRAME_RATE` 對 Surface-input encoder 只是碼率提示、不會真的節流。真正的獨立降頻需要 GL/EGL 丟幀層，經討論後決定暫不做，避免影響已驗證穩定的 Camera2→Surface→MediaCodec 核心 pipeline。

### Phase 5 — GPS Position Integration
- **Implementation：PASS**。新增 `GPSLocationManager`（LocationManager 封裝、多訂閱者 fanout、10 秒 sample buffer、`nearestSample()`）；`H264Encoder` 新增 `toElapsedRealtimeNs()` 建立 pts↔`elapsedRealtimeNanos` 的一次性對應點，作為影像與 GPS 的統一 monotonic 時間基準；`RTPPacketizer` 新增 `packetizeMetadata()`；`RTSPServer` 新增第 4 條 track（ch6/7，payload 99，`m=application`，JSON payload）；`LocalRecorder` 新增 `.gps.jsonl` sidecar，獨立於 MediaMuxer 生命週期。JSON schema 固定為 `{timestamp:ms, latitude, longitude, altitude, accuracy}`，RTSP 與 sidecar 共用同一格式。
- 實機驗證：定位權限流程、`LocationManager` 1Hz request 正確註冊、GPS 從未拿到 fix 時的 best-effort 降級（RTSP/A/V/secondary/recording 皆不受影響，`.gps.jsonl` 正確建立並在 0 bytes 時乾淨關閉）、Start/Stop、全程無 crash。
- **End-to-End GPS Data Validation：PENDING**。測試機在室內，GPS_PROVIDER 超過 60 秒仍未拿到衛星 fix（室內無天空視野，屬預期的物理限制），因此尚未實測 RTSP track4 的實際 GPS 封包內容、`.gps.jsonl` 實際資料、以及 PTS/GPS timestamp 對齊誤差。待有室外環境或裝上 mock-location app 後補測。

## iOS — RTSPCameraServer

### 本 worktree（`.claude/worktrees/dazzling-varahamihira-07671b`）：Phase 3 — Local MP4 Recording
- 依照 Android 已驗證的架構，將 `H264Encoder`/`AACEncoder` 的單一 `onEncodedFrame` closure 泛化為多訂閱者（`addListener`/`removeListener`），比照 Android Phase 2 的 listener pattern，讓 `RTSPServer` 與新增的 `LocalRecorder` 可以獨立訂閱同一組 encoded access units。
